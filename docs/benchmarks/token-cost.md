## Headline

Prompt-hook injection costs **24.9× more** than context-hook injection over a 45-turn session. 
Over a 100-turn session, the quadratic accumulation would make this ratio even more extreme.

Tool-only is the cheapest but has the worst recall — it only retrieves memories 
when the model explicitly calls res_search, which it may not do every turn.

## Recommendation

**Use context-hook injection with `cache: { type: "persistent" }`.**

It provides the best balance of cost and recall:
- Same recall as prompt-hook (93%)
- 24.9× cheaper than prompt-hook
- Only 1542% more expensive than tool-only, but with guaranteed recall

## Methodology

### Setup
- 20 memory records seeded into an InMemoryStore
- 45 simulated user questions about the codebase
- Hybrid search with FTS5 text matching (no vector embeddings in benchmark)
- Injection budget: maxFacts=6, maxChars=2400, minScore=0 (RF fusion scores are small)

### Token estimation
- Method: `Math.ceil(chars / 3.6)` — char-based heuristic
- Error margin: ±20% on English text, ±30% on code
- A real tokenizer (tiktoken) would be needed for production-accurate numbers

### Cost estimation
- Pricing tier: `small` ($0.15/1M input tokens) — e.g., GPT-4o-mini
- Only input tokens are counted; output tokens are constant across strategies

### Configurations

#### 1. Prompt Hook (persisted user input)
Injection is appended to the user message. On the next turn, the model
is billed for ALL previous user messages, including injections. This creates
a **quadratic cost curve**: each injection re-bills on every subsequent turn.

#### 2. Context Hook (transient system part)
Injection is added as a `SystemPart` with `cache: { type: "persistent" }`.
It affects only the **current** model call's input tokens. It does NOT enter
persisted history, so it is never re-billed. The persistent cache means the
provider can cache the injection prefix across turns (Anthropic prompt caching).

#### 3. Tool-Only (no automatic injection)
No injection at all. The model must manually call `res_search` to retrieve
memories. In the benchmark, we simulate the model doing this on ~80% of turns.
This is the cheapest option but has the worst recall.

### Assumptions to challenge

1. **80% tool-use rate** for tool-only — real models may use tools less often
2. **Static memory set** — in production, new memories are added each session
3. **No prompt caching** — Anthropic prompt caching would reduce context-hook cost further
4. **Single project** — cross-project queries would change the injection hit rate
5. **FTS5 only** — vector embeddings would improve recall for semantically related queries
